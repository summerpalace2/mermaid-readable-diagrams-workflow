# 可读技术流程图统一排版与逐图验收工作流

> 用途：把 Mermaid 技术流程图转换为可读、可复核、可维护的图片，并统一到“浅色低饱和网格主题 + 深蓝描边 + 大号中文字体 + 充足留白”的教学图风格。

## 零、规则优先级

当不同规则发生冲突时，统一按以下优先级执行：

1. **技术语义准确**：Mermaid 中的节点、边、方向、分支和消息不能丢失或改写。
2. **用户明确选择**：用户指定的主题模式、固定主题、方向、尺寸策略和逐图确认节奏优先于默认值。
3. **可读性与安全**：文字不可溢出，卡片不可重叠，线路不可穿框、打结或遮挡文字；只有在图形结构本身不支持严格镜像时，才允许降低对称级别并记录例外。
4. **布局策略**：在不违反前 3 条的前提下，遵循中心脊柱、独立通道、Mermaid rank 和动态尺寸规则。
5. **视觉偏好与默认主题**：`paper`、16:9、默认字号和默认语义色只在用户没有提出更具体选择时使用。

因此，后文中的“优先”“默认”“推荐”都是可被上层规则覆盖的建议；“必须”“禁止”才是硬约束。

## 零点一、Mermaid 基线是不可绕过的门槛

每张精确技术流程图必须先产生 Mermaid 原始布局基线，再进入代码优化。这里的“参考 Mermaid”不是只读取节点文字和边，而是必须保留 Mermaid 渲染得到的节点位置、层级 rank、分支顺序、端口方向和原始边路径。

生成过程必须产生以下中间结果：

- `sourceModel`：从 Mermaid 提取的节点、边、标签和消息；
- `baselineModel`：Mermaid 原始渲染的画布尺寸、节点外接矩形、rank、节点中心和边路径；
- `measureModel`：目标字体、换行结果和动态卡片尺寸；
- `layoutModel`：在 `baselineModel` 约束下调整后的节点位置、通道和正交路径；
- `visualModel`：主题、背景、描边、阴影和导出格式。
- `symmetrySpec`：对称模式、对称轴、节点对、边对和验收容差；严格对称时作为 `layoutModel` 的硬约束。

以下条件未满足时，不得生成最终图片，也不得替换正文：

- 没有 Mermaid 原始布局快照或等价的 `baselineModel`；
- 使用与 Mermaid 基线、文字测量和布局约束无关的整套手工 `centers`、`x/y` 坐标或 `path` 路由；允许在这些模型之上使用有依据的锚点坐标、通道坐标和正交路径，但必须说明来源并记录 `layoutException`；
- 无法说明每个最终节点和最终边相对 Mermaid 基线的调整原因；
- 只通过“无重叠、无溢出”检查，却没有完成 rank、出口顺序、方向和线路可读性检查。

如果 Mermaid 原始布局本身难以阅读，可以在基线之上调整方向、间距、卡片尺寸和通道，但必须保留语义顺序和层级关系；任何偏离都要记录为 `layoutException`，不能悄悄改成另一套手工图。`layoutException` 只能描述“为什么调整”，不能成为绕过内容、端点、交叉或对称验收的豁免项。

## 零点二、线对称必须分级并通过几何验收

“对称”不能只凭肉眼描述，必须在生成前分类、生成后测量：

- `strict`：整张图的拓扑和视觉结构都可以关于同一条轴镜像；必须声明对称轴、节点对和边对。对称轴、卡片边界、折点、通道偏移、入边长度和标签位置都必须通过容差检查；失败时不得交付，必须回到 `layoutModel` 或拆图。
- `partial`：整体层级天然不对称，但存在一个或多个可以独立验收的对称子图，例如 `iosArm64Main` 与 `iosSimulatorArm64Main`，或同一决策节点的两个兄弟分支。必须使用 `groups` 为每个子图声明自己的轴、节点对和边对；只能说“局部/分层对称”，不能把局部对称描述成全图对称。
- `none`：时序、树形或信息密度不适合镜像；仍需满足不交叉、不穿框、不贴线和视觉重心稳定，但不强行镜像。

严格对称图必须记录 `symmetrySpec`：

- `axis`：水平或垂直对称轴及其坐标；`partial` 可以在 `groups` 中为每个子图声明不同轴；
- `pairs`：对称卡片对；
- `edgePairs`：对称线路对；
- `publicSpine`：允许共享的公共脊柱边对；未列入其中的同向重叠一律视为非法共享；
- `cardMode`：默认检查完整卡片边界；动态宽度的局部对称可以使用 `inner-edge`，检查两张卡片的内侧入边关于轴镜像，同时要求目标中心线对齐；
- `tolerance`：允许的像素误差，默认不超过 2px；
- `mode`：`strict`、`partial` 或 `none`；
- `groups`：分层对称组列表，每组都必须有 `id`、`axis`、`center` 或 `centerFrom`、`pairs`、`edgePairs` 和验收模式；如果动态宽度使线路端点无法做绝对几何镜像，可以显式标记 `cardOnly: true` 并令 `edgePairs: []`，此时只能声明卡片/内侧入边平衡，不能声称线路对称。`cardOnly` 不能用于逃避可见的成对箭头检查：只要两张成对卡片之间存在语义对应的可见线路，就必须登记 `edgePairs`，否则验收失败。

对称验收至少包括：

1. `strict` 图检查完整卡片边界；`partial` 的 `inner-edge` 组检查内侧入边和中心线，不强迫短标签卡片填充无意义的空白；
2. 成对线路的正交折点和通道关于轴镜像，不能只让卡片位置镜像；
3. 成对线路的有效长度、入边方向和箭头位置一致；
4. 标签和标签底牌位于镜像位置，且不遮挡线路；
5. 全景缩放后再次检查，不能只在局部裁剪图上通过。

补充硬门槛：凡是视觉上呈现为“左右/上下两支”的箭头，都必须在 `symmetrySpec` 中明确归类为 `edgePairs`，或明确标注为“非对称语义边”并采用非对称布局说明；不能只检查卡片而放过箭头。对多个来源汇入同一结果卡片的情况，应先判断是否可以围绕同一中心轴镜像，再决定端口、通道和标签位置；如果可以镜像，必须同时镜像起点、折点、终点和箭头方向。

对称级别的决策顺序固定为：

1. 先检查 Mermaid 拓扑是否存在完整镜像；如果两个子树深度、出口数量或消息数量不同，不得使用 `strict`。
2. 如果只有同一层的兄弟分支可镜像，使用 `partial.groups`；每组单独计算轴、通道、入边和标签，不复用全图中心线。
3. 卡片宽度由文字动态决定时，优先镜像“内侧入边”和中心线，卡片向外增长；只有成对卡片尺寸相同，才允许声称卡片外轮廓也镜像。
4. 如果局部对称会造成穿卡、短线、标签重叠或画布溢出，降低为 `none` 或拆成两张图，不能用硬编码坐标强行补齐。

因此，“全图对称”“分层局部对称”“仅视觉平衡”必须在交付说明中明确区分，禁止使用一个模糊的“对称”概括三者。

本工作流默认优先保证线对称，因此本批次凡是可归类为 `strict` 的图，对称性与无交叉同为硬门槛；不能用“可读性优化”替代未完成的对称验收。

## 一、先区分两类输入

1. Mermaid 源码是内容规范，Mermaid 原始渲染是布局基线：节点、节点文字、箭头方向、分支标签、时序消息和基本层级关系都必须以它为准。
2. 用户提供的参考图片只作为版式规范：背景、字体大小、卡片比例、描边、阴影、箭头粗细和留白。
3. 参考图片中的文字不能覆盖 Mermaid 的技术语义。图片生成模型可以帮助建立风格，但不能作为精确流程图的唯一内容来源。

## 二、内容锁定流程

每张图开始前，先建立一份内容清单：

- 所有节点 ID 与可见文字；
- 所有连线的起点、终点和方向；
- 所有“是 / 否”“成功 / 失败”等分支标签；
- sequenceDiagram 的参与者、消息顺序和取消链；
- Mermaid 中明确表达的回退、循环、并行或异常路径。

完成后必须逐项核对：

- 不漏节点；
- 不漏边；
- 不改变方向；
- 不擅自增加新的业务结论；
- API、类名、函数名、模块名保留原样；
- 普通说明文字优先使用中文。

## 三、统一版式规范

### 1. 画布

- 默认目标比例：16:9。
- 推荐尺寸：1600 × 900；内容复杂时可以按内容等比例放大，或使用可读性更好的宽高比，但必须记录 `aspectException`，不能用超宽条幅压缩内容。
- 四周安全边距：40～60px；如果使用范围框，范围框与画布边缘仍需保留安全边距。
- 节点之间至少保留 36px 空白；不同层级之间至少保留 60px 空白。

### 2. 背景

- 默认主题 `paper` 的底色为 `#FBF9F2`，网格为 `#E6E4DC`。
- 使用约 48px 间距的浅色细网格，具体颜色由选定主题的 `themeModel.grid` 提供，线宽约 1px。
- 不使用纯白空背景，也不使用高对比深色背景、霓虹渐变或装饰性纹理。

### 3. 卡片

- 使用圆角矩形表达步骤、状态、结果和判断问题。
- 圆角约 12～16px，默认使用 14px；圆角只用于柔化边界，不能让节点显得像气泡按钮。
- 深蓝描边：`#26394F`，线宽约 4～5px。
- 使用轻微向下阴影，不能形成厚重的浮雕效果。
- 卡片自然宽度由文字测量结果决定；相邻节点数量影响可用布局宽度、列间距和通道分配，不直接把卡片无理由放大。默认优先加宽矩形，不把长文字硬塞进窄卡片。
- 长标签优先拆成 2 行，最多 3 行；超过 3 行时必须先缩短文案、拆分节点或调整图的层级，不能继续压缩字号；每行都要保持视觉重心居中。
- 卡片内文字左右至少保留约 18px 空白；预计文字宽度超过卡片可用宽度的 80% 时，优先换行或扩大卡片。

### 4. 颜色

默认 `paper` 主题使用以下低饱和语义色；切换主题时只替换具体色值，不改变语义角色：

- 输入 / 外部数据入口：浅蓝 `#C8E1FA`；
- 普通处理步骤：中性白或浅灰；
- 成功 / 共享 / 开启：浅绿 `#CBE8C8`；
- 判断 / 注意：浅黄 `#FFE9A8`；
- 复杂能力 / 平台边界：浅紫 `#E4D3F3`；
- 取消 / 失败 / 风险：浅珊瑚 `#F7CBC5`；
- 中性节点：白色或浅灰。

颜色用于帮助读者分组，不用于替代文字语义。

### 5. 字体

- 中文为主，使用 `Microsoft YaHei`、`PingFang SC` 或等价无衬线字体。
- API、类名、函数名、模块名可以保留英文，例如 `Flow`、`collectLatest`、`StateFlow`、`ViewModel`。
- 普通主节点：28～32px；
- 两行长标签：26～29px；
- 分支标签：18～20px；
- 字重使用 700～800，行距约为字号的 1.15～1.25 倍。
- 文字估算宽度必须小于卡片内宽，至少保留 18px 左右内边距。

## 四、箭头和布局规则

- 使用轻量但清晰的箭头，推荐线宽 3～3.5px。
- 普通流程图统一使用 `16×12px` 箭头头部；时序图保留已确认的 `24×16px` 专用尺寸。两者都禁止使用夸张的大三角箭头。
- 箭头尽量使用水平或垂直直线；必须绕行时只使用短正交折线，避免长斜线穿过其他节点。
- 箭头不能穿过卡片；如果路径必须绕行，应在卡片外侧留出明显通道。
- 箭头数量只由 Mermaid 的真实语义决定，不额外添加装饰线；当视觉上显得箭头过多时，通过重新排布节点、缩短路径和集中分支来降低密度，不能直接删除语义边。
- 长流程优先使用两行阶梯、蛇形布局或分层布局，不使用九个以上节点的单行压缩布局。
- 判断节点默认使用宽一些的圆角问题卡片，并通过“是 / 否”标签表达分支；不为了追求 Mermaid 几何形状强行使用巨大菱形。
- 整组节点应在画布中部形成稳定重心，避免全部挤在左上角或被长箭头拉到边缘。

## 五、单张图片的执行步骤

1. 从 Mermaid 源码提取节点、边、分支和消息清单。
2. 使用 Mermaid 渲染器生成原始布局，保存 `baselineModel`，包括画布、节点矩形、rank、出口顺序和边路径。
3. 判断流程类型：线性流程、分支决策、状态闭环、时序链路或分层架构。
4. 以 `baselineModel` 为骨架建立布局草图，只放卡片占位和 rank/列关系，不生成最终线路；禁止先凭感觉摆放全部节点。
5. 根据文字长度动态调整卡片宽度、卡片高度、换行位置和节点间距；先保证文字比例，再重新计算通道和线路，不能让旧的固定路径继续依赖旧卡片尺寸。
6. 按本规范添加网格背景、描边、阴影、语义色和字体；优先形成“宽卡片 + 大字号 + 留白”的直观层级。
7. 将 Mermaid 的全部内容填回图片，API 与类名保持准确。
8. 做结构检查：节点、边、分支、方向、rank 顺序和文字全部匹配。
9. 做几何检查：卡片不重叠、所有路径不交叉、箭头不穿框、文字不越界、端点法向正确、公共脊柱已声明、画布比例合理；QA 必须自动发现并覆盖本轮实际生成的每一个 SVG，不能因手写文件清单漏登记而形成假通过。
10. 做视觉风险检查：末段箭头是否显形、平行线是否过近、折点是否形成视觉打结、标签是否切断线路、整体重心是否失衡；风险必须标出具体边对和坐标，不能只写“图不美观”。
11. 在正文和交互页面中预览图片，确认缩放后仍然清晰。
12. 一次只提交一张图片给用户确认，确认后再处理下一张；只有用户明确要求 A/B 对照时，才允许把两个实验版本作为同一比较批次展示，仍不能批量替换。

## 六、交付前验收标准

一张图只有同时满足以下条件，才算完成：

- 内容与 Mermaid 逐项对应；
- 中文说明清晰，特殊技术名词准确；
- 背景、字体、卡片、描边、阴影和箭头符合统一风格；
- 箭头不抢过文字和节点，且大多数路径可以沿水平/垂直方向快速读完；
- 文字与卡片的长宽比例协调，缩放后不会挤成一团；
- 最终节点的 rank、出口顺序和主要层级关系与 `baselineModel` 一致；
- 每条最终边都能追溯到 Mermaid 原始边，布局偏移有明确原因或 `layoutException` 记录；
- 卡片重叠数为 0；
- 箭头穿过卡片数为 0；
- 所有线路的内部交叉数为 0，允许的节点端点连接除外；
- 非对称图的同向共享线段数为 0；严格/部分对称图的共享线段必须同时出现在已声明的 `publicSpine` 与 `edgePairs` 中，不能因为 `symmetry.mode` 不是 `none` 就自动放行；
- `strict` 图的对称验收通过；`partial` 图的声明节点对和边对验收通过；`none` 图明确记录不适用原因；
- 严格对称图的卡片中心、线路折点、通道、入边和标签镜像误差不超过 `symmetrySpec.tolerance`；
- 文字越界数为 0；
- 范围框内的节点必须通过 `zoneInset` 安全区检查；节点、描边和主要阴影不得越过所属范围框；
- 画布比例符合当前选择的规格，默认保持 16:9；
- SVG/XML 可解析；
- 普通流程箭头实际为 `16×12px`，时序箭头实际为 `24×16px`；箭头尺寸必须从成品 SVG 元数据和 marker 双重核对，不能只相信配置常量；
- `SHORT_ARROW`、`PARALLEL_MERGE` 和重心失衡属于视觉风险：若超过当前图的 `visualConstraints` 或没有明确 `visualAllowance`，应回到 `layoutModel` 修正；在历史图兼容阶段可以先作为阻断前的警告，但必须出现在报告中；
- 正文和 HTML 的资源路径有效；
- 用户能在当前对话中看到最终图片，而不是只收到文件名。

## 七、严格替换原则

当图片用于替换 Mermaid 时：

- 先保留 Mermaid 源码备份；
- 先完成内容等价检查，再删除正文 Mermaid；
- 不把“附近有一张相似图片”视为替换完成；
- 对文字密集的精确流程，优先使用确定性 SVG；
- 图片生成模型只用于风格探索、背景探索或非精确概念插图；如果要生成精确流程图，模型输出只能作为版式参考，不能让模型自由改写技术节点、文字、箭头关系或线路端点，最终成品仍必须由确定性布局与 QA 生成。

## 八、卡片尺寸的动态选择

### 方案 A：同高、宽度随文字变化

- 适合步骤层级清晰、希望上下边缘整齐的流程图。
- 内容较多的节点通过增加宽度获得空间，内容较少的节点保持较窄。
- 优点是同一行的视觉节奏稳定，适合横向主流程。
- 风险是不同节点宽度差异过大时，需要重新计算箭头和画布中心。

### 方案 B：同宽、高度随文字变化

- 适合需要纵向对齐、希望节点列保持一致的决策图或分层图。
- 内容较少的节点降低高度，内容较多的节点增加高度。
- 优点是列对齐和箭头定位简单，整体更像结构化表格。
- 风险是上下边缘不齐，长文本节点可能造成局部高度突变。

### 选择规则

- 横向主链、步骤流、发布链：优先尝试方案 A。
- 多列决策、状态分组、上下游对齐：优先尝试方案 B。
- 两种方案都必须先用同一份内容清单生成 A/B 预览，再根据留白、重心、箭头密度和缩放可读性选择。
- 没有用户确认前，A/B 实验图只作为预览，不替换正文主图。

### 最小 A/B 对照法

当用户无法直观看出两种尺寸策略的差异时，不直接拿完整流程图比较。先从同一张图中选出一条短标签和一条长标签，制作两张只包含这两个卡片的实验图：

- 实验图 A：卡片高度相同，短标签和长标签的宽度差异明显；
- 实验图 B：卡片宽度相同，短标签和长标签的高度差异明显；
- 实验图下方标出实际宽高，帮助用户判断“动态调整”是否真实发生；
- 实验图不放复杂箭头和其他节点，先确认卡片比例，再回填到完整流程。

如果 A/B 视觉差异仍不明显，优先扩大尺寸差异或减少文字变量，不要继续增加节点、颜色和装饰。

## 九、Mermaid 比例基线与代码优化

### 1. Mermaid 负责提供什么

- Mermaid 源码负责提供节点文字、边、方向、分支和基本布局关系。
- Mermaid 原始渲染的节点相对尺寸、层级间距、分支位置、出口顺序和边路径必须写入 `baselineModel`，作为图片布局的初始比例。
- 不能只读取 Mermaid 的语义而完全重新凭感觉摆放节点；否则容易出现文字变化很小、卡片却异常变宽，或流程方向与原图脱节的问题。
- 如果当前环境不能调用 Mermaid 渲染器，必须先补齐渲染依赖或使用已保存的可信基线，不能用手工坐标假装基线。

### 2. 代码负责优化什么

代码只在 Mermaid 基线之上做有限度优化：

- 用目标字体测量每一行文字的实际宽度；
- 根据文字测量结果自动计算卡片宽度和高度；
- 对接近边界的文字优先换行，而不是无限增加宽度；
- 保留 Mermaid 的相对间距，再做居中、避让和局部压缩；
- 重新计算短水平线、短垂直线和必要的正交折线；
- 对同一布局中的卡片使用受控范围，避免短标签和长标签出现不合理的倍数差异。
- 不允许直接维护一套与 `baselineModel` 无关的完整 `centers` 坐标表或整组手工 `path`；确需例外时，必须记录基线坐标、调整原因和影响范围。

### 3. 尺寸计算约束

- 卡片宽度不能直接写成与内容无关的固定大值；
- 推荐先按“文字测量宽度 + 左右内边距”计算自然宽度；
- 设置合理的最小宽度和最大宽度，超过最大宽度时换行并增加高度；
- 卡片高度由行数、字号和行距计算；
- 同高模式只允许宽度在受控范围内变化；同宽模式只允许高度随行数变化；
- A/B 对照必须使用同一份 Mermaid 节点数据，不能同时改变内容、布局和颜色。

### 4. 实现分层

图片生成代码分成六层，避免把内容、Mermaid 基线和版式写死在一起：

1. `sourceModel`：Mermaid 节点、边、分支和消息；
2. `baselineModel`：Mermaid 原始渲染的画布、节点矩形、rank、出口顺序、端口和边路径；
3. `measureModel`：字体、行宽、换行和卡片自然尺寸；
4. `layoutModel`：在 Mermaid 基线约束下调整的节点位置、间距和箭头路径；
5. `visualModel`：背景、网格、描边、阴影、颜色和导出格式；
6. `symmetrySpec`：对称模式、对称轴、节点对、边对和验收容差，作为 `layoutModel` 的硬约束。

任何一张图如果需要手工修改，优先修改对应层的数据或约束，不直接在 SVG 中堆叠坐标补丁。

### 5. 当前执行策略

- 至少先用一张代表性流程图完成“Mermaid 基线 + 代码优化”验证，后续图片再复用这套规则；
- 每张新图仍然先展示结果，确认卡片比例、字体、主题和箭头密度；
- 用户确认后再处理下一张图，不因为算法已经验证就批量覆盖；
- 未确认前，不批量重绘其它图片。

### 6. 流程线防打结约束

#### Mermaid 源码侧

- 明确声明流程方向：主链较长时优先 `flowchart LR`，分层决策较多时使用 `flowchart TD`；不要让后期代码猜测方向。
- 先做 Mermaid 拓扑可读性检查，再生成基线：如果一张图同时混合读取闭环、刷新链、写回和异常出口，必须先用 `subgraph` 按语义分区，并明确每个区域的 `direction`；不能等渲染阶段用大回线补救混乱拓扑。
- Mermaid 结构重构只能改变分区、方向和布局约束，不能删除、合并或偷偷改写原有节点、边和分支语义；重构完成后必须重新生成 Mermaid 基线，旧基线不得继续复用。
- Mermaid 节点标签包含 `()`、方括号或其它语法敏感字符时，必须使用 Mermaid 引号包裹标签，并在解析器中去除包裹引号；先通过 Mermaid CLI 语法校验，再进入布局计算。
- 保持同一条语义路径的层级连续，尽量避免跨越多个层级的回接边；确实需要回接时，应先在源码中拆成清晰的阶段或子图。
- 分支节点的出口顺序要稳定，必要时使用 `subgraph` 或记录过的不可见约束固定顺序；不可见边只能用于稳定布局，不能改变语义。
- Mermaid 中的节点、分支标签和边是唯一内容来源；后期可以改方向和排版，但不能删除、合并或凭感觉补线。

#### 后期渲染侧

- 先按 Mermaid 的 rank 和节点顺序排出列/行，再计算卡片尺寸，最后进行边路由；不能先画线再移动卡片。
- 渲染顺序固定为“卡片 → 连线/箭头 → 分支标签”，让箭头贴边可见；标签底牌必须离开线路安全间隔，不能用不透明底牌把线路截出缺口。
- 动态宽度卡片的通道必须在路由后计算：若目标卡片位于右侧，最后一段必须从通道向右进入目标左边界；禁止复用固定通道导致最后一段向左回走、箭头背向目标。
- 带有范围框/语义分组的图必须声明 `zoneCards` 与 `zoneInset`：每个归属节点的外接矩形（含描边）都要落在范围框内，并至少保留 36px 内缩；不能只把范围框画大或依赖画布裁切来掩盖越界。
- 相邻 rank 之间预留“通道区”，通道数量由该区实际需要的分支边数计算；通道不足时应扩大间距或改变布局，不得把多条线挤在同一条竖线上。
- 一般分支和同一列间隙中的不同分支，都要分配独立通道；分支拆开后不能再次共享中继竖线。
- 非对称决策树不能为了省线而复用父节点到分叉点的共享线段；每条语义边都要从来源卡片边界独立出线，并在目标卡片边界收线。唯一例外是明确声明的 `publicSpine`：最小声明是具体 `edgePairs`，渲染器再从实际路径记录共享通道和共享范围并核验，不能仅凭 `strict` 或 `partial` 模式自动放行。
- 当一个父节点有两个同层级结果，且没有其它节点阻挡时，优先让两个结果以父节点中心线为基准对称展开；上下布局使用对称的纵向间距，左右布局使用对称的横向间距。
- 对称展开不能破坏语义顺序：先保持 Mermaid 的出口顺序，再在可用空间内做镜像排列；如果对称会导致卡片相撞、线路穿越或文字不可读，应优先满足可读性并记录例外。
- 对称不仅适用于卡片位置，也适用于两条分支的折点和通道；不能卡片看似对称、线路却挤在同一侧。
- 如果目标是严格的上下镜像，且父节点、两个目标和可用空间确实形成同一分叉结构，中心脊柱是一般独立通道规则的明确例外：不能用两条左右错开的竖线“模拟对称”，应使用位于分叉中心的连续竖向脊柱，父节点水平接入脊柱，上下端点再分别水平接入目标卡片。脊柱本身不放箭头，箭头放在两个目标入边上，避免中心线出现多余箭头或打结；若拓扑或空间不满足这些条件，改用独立 lane 并降低对称级别，不能强行套用中心脊柱。
- 中心脊柱方案下，两个目标卡片的入边边界应保持一致；分支标签放在上下入边的镜像位置，并以背景底牌隔离线路。只有卡片中心、脊柱、入边和标签同时满足镜像关系，才算真正的对称展开。
- 全景验收要同时观察三个中心线：父节点到子节点的中心距离、同一目标列的入边起点、分支标签的位置；只满足其中一个，不能称为整体对称。
- 当同层结果卡片宽度不同而又追求等长入边时，应统一目标列的入边边界，让卡片宽度向外增长；不要把卡片都居中后再接受两条明显不同的边长。
- 分层局部对称时，每个 `symmetrySpec.group` 都必须拥有独立的标签安全区；相邻决策层不能把两组“是 / 否”标签放在同一条水平线上。优先把下层标签放到其独立竖向通道的中段，并与通道留出背景间隔。
- 对动态宽度卡片，优先镜像“内侧入边 + 折点 + 标签”，卡片向外侧增长；如果采用卡片中心镜像却导致两条入边长度明显不同，应改用内侧边界模型，不能只在视觉上移动标签补救。
- 对称检查必须放在缩放后的全景图上进行，不能只看局部裁剪；局部“没有相交”不代表全图没有视觉打结或重心偏移。
- 正交折线必须避开所有卡片外接矩形，并与卡片边界保留安全距离；禁止出现折回、贴边绕行或穿过旁路节点的路径。
- 每条边必须做“端点连接”验收：起点落在来源卡片边界、终点落在目标卡片边界；不能只在视觉上靠近，也不能在线路中间断开。生成代码应在导出前对 Mermaid 的每条边逐条检查起点、终点和路径存在性。
- 端点落在目标卡片边界仍然不够：必须检查最后一段的进入方向与目标边界法向一致。进入左边界时最后一段必须水平向右，进入右边界时必须水平向左，进入上边界时必须垂直向下，进入下边界时必须垂直向上；禁止沿卡片边界贴行后用反向箭头“碰到”目标。
- 几何验收要区分“合法公共脊柱”和“非法线路重叠”：同向线段重合只允许出现在已声明的 `publicSpine` 且属于对应 `edgePairs` 的范围内；普通 `none` 决策图出现共享线段即判为打结风险。真正的横竖交叉、穿卡和端点脱离都直接阻断导出。
- 分支标签放在目标卡片的入边附近，并提供与背景同色的留白底牌；线条不能穿过标签底牌，也不能让标签贴住另一条路径。
- 验收不能只看“箭头是否相交”，还要检查：通道是否过近、平行线是否像一条粗线、折点是否形成打结、标签是否落在线路或卡片文字区域。
- 闭环或回写图必须先分离“主观察环”“刷新链”“回写边”“失败出口”四类路径；回写边优先走外侧独立 lane，不能穿过主链节点，也不能和主观察环长距离共线。
- 回写到目标卡片时，路径必须先选择合法的边界端口，再从目标外侧接入；禁止从卡片下方穿过卡片内部去连接顶部端口。一个目标卡片存在多个入边时，应使用分离的左/右/上/下端口，并检查端口之间的安全间距。

### 7. 约束 IR 与候选路由

为了避免“动态卡片尺寸”和“手工固定线路”再次互相覆盖，`layoutModel` 不再把坐标当成唯一事实，而要先形成一份可检查的约束中间表示（Constraint IR）：

- `rank / row / column`：来自 Mermaid 基线的层级与出口顺序；
- `anchor`：卡片相对 rank、列或中心轴的定位依据；
- `port`：来源和目标允许使用的边界端口；
- `lane`：线路所属的独立通道；
- `symmetryGroup`：成对卡片、成对边、轴、镜像模式和容差；
- `avoid`：必须避开的卡片、线路、标签安全区和范围框；
- `visualConstraints`：最小末段长度、最小平行间距、允许的公共脊柱以及是否阻断。

生成路线时至少产生两个候选方案；每个候选方案都先经过硬约束过滤，再按视觉风险评分选择：

`score = 交叉×10000 + 穿卡×10000 + 反向入边×10000 + 非法共享×10000 + 对称误差×1000 + 平行线近距×1000 + 短末段×300 + 重心失衡`

候选方案全部失败时，必须扩大列间通道、调整 rank、拆分图片或降低对称级别，并记录原因；不能直接采用“看起来差不多”的最后一条路径。当前已有图的手工坐标可以继续维护，但必须视为由上述约束推导出的 `layoutException`，新增图片不得复制未经解释的数字坐标。

- **硬阻断项**：节点/边/方向不一致、卡片重叠、路径穿卡、真实交叉、端点未连接、目标边界法向错误、未声明共享线段、范围框越界、箭头规格错误；
- **视觉警告项**：末段短于 48px、平行线间距小于 48px 且投影重叠超过 32px、标签贴线、重心失衡。警告必须输出边对和数值；如果该图没有明确 `visualAllowance`，新图应在用户预览前修正，历史图兼容期才允许带警告交付。

#### 推荐路由顺序

`解析 Mermaid → 生成 baselineModel → 计算 rank → 测量文字 → 计算卡片 → 声明 symmetrySpec → 计算列间通道 → 判断是否严格镜像 → 选择中心脊柱或独立 lane → 绘制正交边 → 放置标签底牌 → 做对称、全路径相交与近距离检查`

这意味着 Mermaid 负责“应该连接谁”，渲染代码负责“怎样连接才容易读”；如果两者都无法在一张图中保持清晰，应优先拆图，而不是继续叠加折线。

## 十、主题色轮换规范

为了避免同一篇文章所有图片都使用同一种米白色，同时保持统一的教学风格，允许使用低饱和主题色轮换。一个主题不是单独的背景色，而是“画布背景 + 网格 + 卡片背景色 + 辅助文字色”的完整配色包。主题只改变 `visualModel`，不改变 Mermaid 内容、布局几何、深色文字或箭头规则。

### 1. 主题调色板

| 主题 | 画布背景 | 网格 | 卡片配色倾向 | 使用感觉 |
|---|---|---|---|---|
| `paper` | `#FBF9F2` | `#E6E4DC` | 柔和蓝 / 黄 / 绿 / 紫 / 珊瑚 | 默认纸张、最稳定 |
| `mint` | `#F3FAF7` | `#DCEBE7` | 薄荷蓝 / 鼠尾草绿 / 淡紫 | 生命周期、状态流、协作 |
| `warm` | `#FFF8ED` | `#EFE1D1` | 奶油黄 / 杏色 / 暖紫 | 业务流程、迁移、工程实践 |
| `mist` | `#F4F7FB` | `#DDE5EF` | 雾蓝 / 冷绿 / 冷紫 | 编译链、平台边界、架构 |

每个主题都继续使用深蓝 `#26394F` 作为主文字、边框和箭头颜色。卡片背景按语义角色保留稳定映射：输入使用蓝色，判断使用黄色，成功或可继续使用绿色，中性步骤使用白色，取消或终止使用珊瑚色，复杂能力使用紫色，弱化信息使用灰色。不同主题可以改变这些角色的具体色值，但不能改变角色含义；不能使用霓虹色、高对比渐变或纯黑背景。

### 2. 生成前主题选择（必须先询问）

以后只要启动这套图片生成或重绘流程，第一步必须先向用户确认主题模式，不得默认替用户选择：

> 本次使用哪种主题？
> 1. 随机主题：从 `paper`、`mint`、`warm`、`mist` 中选择一套，并记录最终选中的主题；
> 2. 固定主题：请指定其中一套，例如 `mint`。

如果用户选择随机主题，生成结果必须在文件名、日志或交付说明中记录实际主题，确保后续复现；如果用户选择固定主题，则整组图片沿用该主题，除非用户再次要求切换。用户没有回答前，可以继续做源码解析、内容核对和布局分析，但不要生成或覆盖最终图片。

### 3. 轮换规则

- 主题选择优先级固定为：用户指定的固定主题 > 用户授权的随机主题（当前批次抽取一次后冻结） > 用户授权的章节确定性轮换 > 默认 `paper`。
- 只有用户明确选择或授权时才允许随机或自动轮换；用户选择固定主题时不得自行轮换。
- 随机主题只能在本批次开始时抽取一次；记录日志返回的实际主题后，后续同批次图片改用这个固定主题名，不能每张图重新随机。
- 如果用户授权按章节自动轮换，使用确定性顺序：`paper → mint → warm → mist → paper`，并在章节配置中记录起始主题。
- 同一组连续讲解图可以保持同一主题；跨主题切换时优先在章节边界切换，不在同一张图内部混用多套背景。
- 在用户没有指定固定或随机主题时，重要主图、复杂总图和需要打印的图优先使用 `paper`；辅助图可以使用 `mint`、`warm` 或 `mist`。
- 主题色不能掩盖语义色：输入、判断、成功、取消和复杂能力仍保持稳定的颜色角色。
- 主题切换后必须重新检查文字与卡片、网格与背景、箭头与背景的对比度；对比度不足时回退到 `paper`，不能为了色彩变化牺牲阅读。

### 4. 主题化实现

渲染器使用 `themeModel` 统一提供 `bg`、`grid`、`ink`、`muted` 以及 `cards.input`、`cards.success`、`cards.decision`、`cards.neutral`、`cards.accent`、`cards.cancel`、`cards.complex` 和 `cards.quiet`，禁止在单张 SVG 中散落背景色常量。固定主题示例：

`kmp-exact-08-flow-operators-v5-lr-mint.svg`

渲染器命令约定：

- 固定主题：`npm run render -- mint`；
- 随机主题：`npm run render -- random`，日志必须回显实际选中的主题；
- 未指定主题只用于兼容旧脚本，默认 `paper`，正式工作流不能跳过“生成前主题选择”。

主题变化只进入 `visualModel`，不能反向修改 `sourceModel`、`measureModel` 或 `layoutModel`。同一张图生成多个主题预览时，节点坐标、卡片尺寸、折点、通道和文字必须完全一致，方便比较主题本身而不是比较排版变化。

主题预览与尺寸 A/B 实验必须分开：主题预览只改变 `visualModel`；A/B 实验只改变明确的尺寸策略，不能同时更换主题，否则无法判断差异来自配色还是布局。

## 十一、全局一致性审查（2026-09-16）

本次审查同时对规则文本、渲染器和 20 张现有 SVG 做了回归，发现并统一了以下曾经互相打架的地方：

| 原有不顺畅点 | 统一后的规则 |
|---|---|
| “不能手工坐标”与实际需要动态排版冲突 | 禁止无依据的整套手工图；允许从 Mermaid rank、文字测量、锚点和通道约束推导坐标，并记录 `layoutException`。 |
| “有对称模式就能放行共享线”过宽 | 只有明确登记为 `publicSpine` 且命中对应 `edgePairs` 的共享线段才合法；其它共享线段直接阻断。 |
| 只检查端点接触，未检查箭头从哪一侧进入 | 端点连接与目标边界法向是两个独立硬门禁；左/右/上/下边界分别要求向右/向左/向下/向上进入。 |
| 卡片动态变宽后继续复用旧 path | 先测量卡片，再计算通道和候选路由；线路不能引用未重新计算的固定边界。 |
| “所有图 16:9”与复杂图实际需要更高/更宽冲突 | 16:9 是默认目标；复杂图可以使用更适合阅读的比例，但必须记录 `aspectException`，不能压扁内容。 |
| “一次一张”与 A/B 对照冲突 | 普通流程一次只提交一张；只有用户明确要求时才展示 A/B 比较批次，且仍逐批确认、禁止直接批量替换。 |
| Mermaid 重构和后期渲染职责边界不清 | Mermaid 负责语义、方向、分区和基线；代码负责动态尺寸、端口、通道和可读路线；任何 Mermaid 结构重构都必须重新生成 baseline。 |
| `crossings=0` 被误认为“图一定好看” | 增加平行线近距、短末段、标签贴线、折点打结和重心的视觉风险检查；技术通过不等于视觉通过。 |
| QA 手写文件清单可能漏掉新增图 | QA 自动发现目录中所有 `kmp-core-preview-*.svg`，并在报告中显示发现数量；不能手工漏登。 |
| 图片模型可能被误用为精确流程生成器 | 模型只负责风格/非精确插图参考，精确节点和连线必须回到确定性 SVG、约束路由和 QA。 |

### 唯一的决策优先级

发生冲突时，不再在不同章节分别解释，统一按此顺序决策：

1. 技术语义与 Mermaid `sourceModel`；
2. 用户明确指定的方向、主题模式、尺寸策略和确认节奏；
3. Mermaid `baselineModel` 的 rank、出口顺序和层级关系；
4. 几何安全：端点、法向、穿卡、交叉、范围框和箭头规格；
5. 已声明且可实现的对称约束；
6. 可读性：文字比例、通道间距、标签安全区、视觉重心和缩放清晰度；
7. 主题与装饰风格；
8. `paper`、16:9 等默认建议。

“默认”不能覆盖用户选择；“可读性优化”不能覆盖语义和几何硬门禁；“对称优先”也不能为不可实现的拓扑强行造线。所有例外必须显式写入 `layoutException`、`aspectException` 或 `visualAllowance`，不能依赖口头解释。

### 当前回归结论

- 渲染器已输出箭头规格和对称边对元数据；普通流程检查 `16×12px`，时序图检查 `24×16px`。
- QA 已自动发现并检查现有 20 张 SVG；卡片重叠、穿卡、真实交叉和非法共享线段均为 0。
- 近距平行线和短末段会继续以具体边名、间距和长度输出为 `visualWarnings`，不能被结构通过掩盖；历史图可在兼容期保留警告，新图在用户预览前应修正。
- 本次回归中发现的旧路由错误已回到 `layoutModel` 修正，没有通过裁切、遮挡或放宽规则处理。
- 通用的多候选路由求解器尚未完全自动化；当前 20 张旧图仍保留每图确定性 `routes`，但已经受到渲染前硬门禁和全量 QA 约束。后续复杂新图必须提供候选记录或明确的回退方案，不能把旧图的手工路径误当成自动推导能力。

## 十二、最终可复用流水线

`询问主题模式 → 读取 Mermaid 源码 → 建立 sourceModel 内容清单 → 生成 Mermaid 原始布局与 baselineModel → 选择方向与固定/随机主题 → 建立 Constraint IR → 计算 rank 与锚点 → 测量文字并动态计算卡片 → 预留列间通道与端口 → 声明 symmetrySpec/publicSpine → 为复杂图生成至少两个候选正交路由（简单图至少保留一个可解释的回退方案）→ 硬约束过滤与视觉风险评分 → 选优路线 → 放置标签底牌 → XML/内容/rank/端点法向/几何/全路径/对称/视觉风险/全景验收 → 自动发现全部 SVG 做回归 → 生成预览 → 用户逐图确认 → 更新正文与交互页`

任何一步验收失败，都回到对应层修正：语义错误回到 `sourceModel`，基线或方向错误回到 `baselineModel`，文字和卡片问题回到 `measureModel`，打结、不对称、端点或路由问题回到 `layoutModel`，颜色与背景问题回到 `visualModel`。确认前不批量覆盖正文图片。
